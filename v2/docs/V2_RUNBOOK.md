# 陕西资本市场日报 V2 运行手册

## 数据内核

`v2/config/source-contract.json` 是唯一来源契约。正式输入包括：

- 上市公司 110 家观察池、业务分类、同日公告和客户摘要；
- 私募 92 家观察池、50 条迁移后去重年库和同日 AMAC 快照；
- 25 个收并购项目（24 个正式原文已核验，1 个历史精确原文待补）；
- 金融招投标和国企动态年度事件源；
- `events/unified-2026.json` 统一事件库及 `observation-pool.json` 统一观察池。

统一事件字段包括稳定 `eventId`、相关主体、陕西关系、阶段、关键事实、原始来源、
进展时间线、扫描日期和最新事件日期。同一项目后续进展只追加时间线。

V1/V3 源码不在当前主分支。日常 V2 数据运行不得读取旧版本的同日数据、图片、网页或
交接清单；所有运行输入必须归属于本文件列明的 V2 路径。

## 来源与失败关闭

来源优先级依次为交易所/监管原文、发行人原文、官方公开披露。媒体只发现线索，
不能确认关键数字。上市公司必须有同日 raw 和 curated；私募年库按 `fundNo` 保留历史；
涉及上市公司的收并购项目必须有交易所原文。

每一时点的五栏目扫描记录位于 `v2/data/scans/`：

正式生产入口默认以 05:30、12:00、17:00 作为计划启动时点；超过 60 分钟才启动的
production 运行会失败关闭并留下运行清单，不能用迟到数据覆盖成“按时早报”。下一时点
应按完整补偿执行，而不是复用迟到的栏目状态。

- `completed`：扫描完成且有可确认内容；
- `no_new`：扫描完成、今日无新增；
- `failed`：扫描失败。

`write_v2_readiness.py` 为同日期、同时点的五栏目生成栏目级门禁：

- 五栏全部完成、原文证据和质量合同均通过时为 `ready`；
- 任一必需来源受限、观察池或快照漂移、原文缺失或核心栏目未完成时为 `blocked`；唯一例外是
  招投标回执明确证明官方等价覆盖完整、且受限者仅为合同中声明的补充来源，此时仍可 `ready`，
  但客户页必须标记“已完成扫描，来源受限”。

`blocked` 停止构建和发布；旧事件绝不得写成当天更新。

`record_channel_scan.py` 只是状态登记器，本身不执行抓取。MA、tender 与 SOE 均有
专用 V2 刷新脚本：

- `refresh_ma_events.py` 读取 V2 同日 110 家上市池公告结果和 L2 港股复核回执，
  扫描收购、出售、股权转让、控制权变更、增资、重组、交割、工商变更和终止等事项；
- `refresh_tender_events.py` 扫描陕西公共资源、陕西政府采购正式列表 API、
  陕西采购与招标公开 API 和中国招标投标公共服务平台；主站受验证码阻断时只允许
  由配置中声明且查询矩阵完整的官方等价覆盖组补位；
- `refresh_soe_events.py` 要求同日同时点的 V2 证据批次并逐条核验官方原文。

三者都会写 `source/<channel>/scans/` 回执。MA/tender 还分别写 raw、candidates 和
exclusions，正式事件库只接受已取得官方正文且字段足以核验的记录。就绪检查验证同日、
同时点、覆盖状态、网络核验、事件库 SHA-256 及所有审计产物 SHA-256，避免
“只声明扫描完成、实际事件库未刷新”的风险。

SOE 证据批次位于 `v2/data/source/soe/evidence/verified-YYYY-MM-DD-SLOT.json`。
其中必须记录扫描结论、有效事项、原始URL、标题/日期校验字段和排除项。日常运行不读取
任何旧版本或独立看板页面；历史批次中的迁移页面路径仅是一次性审计说明，
`runtimeInput=false`，构建输入全部为 V2 自有数据。

## 三个自动化时点

首次部署或依赖版本变化时，由维护任务执行一次：

```bash
sh v2/scripts/bootstrap_runtime.sh
```

生产任务不得调用工作区依赖加载器、`pip install` 或修改代码。三个时点均只调用同一个
入口：

```bash
sh v2/scripts/run_daily_v2.sh --date YYYY-MM-DD --slot morning --publish
sh v2/scripts/run_daily_v2.sh --date YYYY-MM-DD --slot midday --publish
sh v2/scripts/run_daily_v2.sh --date YYYY-MM-DD --slot closing --publish
```

统一入口并发执行上市公司原文、AMAC 私募和 SOE 官方证据准备，随后扫描 MA、tender、
SOE，并只执行一次统一事件库、readiness、构建、验证和发布。每次运行无论成功或失败，
都会在 `v2/data/runs/` 写终态清单，包含阶段耗时、栏目状态、来源失败、数据哈希和已发布
版本，不再遗留 `in_progress`。

发布成功的定义不是“git push成功”，而是线上
`/v2/data/production-data.json` 的 `asOf` 等于本次运行日期、构建版本等于本地
`build-version.json`，且六个客户页面均返回当前版本。线上仍为旧日期时自动化必须
保持失败状态，不得归档。

运行顺序为：五栏正式来源获取与专用扫描 → 统一事件库 → 栏目就绪清单 → 客户网页 →
全量测试 → 从 V2 冻结快照生成四张日图 → 发布 → 线上版本与日图校验
→ IMA 上传/补传。私募和收并购网页保留全年记录，但不再生成三个月分享图。

## 日图、栏目归档与 IMA

V2 归档四类每日图片：上市公司、证券私募、收并购、金融招投标。图片仅由首个完成五栏
门禁的 V2 不可变生产快照生成，逐张记录快照哈希、构建版本和图片 SHA-256。12:00 和
17:00 只更新网页；若 05:30 阻断，后续首次完整补偿才从当时冻结的 V2 快照生成当天唯一
日图。

图片先进入 `v2/.runtime/` 临时缓存，发布到线上各栏目 `archive/daily/` 后才标为已归档。
V2 本机不保留新的 PNG 副本；每次 IMA 尝试结束即清理 V2 临时图片。IMA 临时失败不阻断
网页，午间、收盘与次日早间会从同日冻结快照精确重绘，再按图片哈希校验。上传以完整文件名检索命中为完成标准，
发现重名但无法确认同一文件时停止并标为人工复核，绝不自动追加重名后缀。

`v2/data/daily-image-archive.json` 是栏目图片索引；客户页面只展示日期、栏目和历史期次，
默认只显示最新一期，历史期次按年份展开，不显示内部 IMA、哈希或调试信息。最新期次显示
“最新V2日图”。已发布的历史日图只作为不可变客户归档保留；当前源码不提供旧版本导入
命令，也不会从旧版本目录重建或补传图片。

当前覆盖边界（不得扩大口径）：

- MA 已实现西部产权交易所 11 类挂牌/预披露项目及成交、中止/终结公告，
  但候选仅覆盖股权、增资、控制权、企业产权和整项业务/经营性资产交易；
  车辆、单宗土地/房产、报废物资、设备、存货及租赁权等单项实物处置默认排除。
  “完成、终止、交割、工商变更、交易”等生命周期词不得单独构成 MA 命中。
  陕西国资委覆盖企业动态/信息要闻/通知公告，
  以及 `ma-issuer-sites.json` 正式企业官网注册表逐站扫描。注册表内站点要求 100%
  成功；其余 21 个项目相关主体保留在 coverage backlog，不声称覆盖全陕西企业；
- tender 的陕西公共资源和中国招标投标公共服务平台执行同日完整关键词矩阵。
  陕西采购与招标主站可取得首屏列表，但当前翻页触发验证码；其覆盖组仅在中国招标
  投标公共服务平台完成“同日×陕西×16关键词×4阶段”且当日命中正文全部核验时成立；
- 陕西政府采购网已实现与前端一致的签名全文列表请求，但验证码属于外部访问限制。
  在“独有覆盖回测”完成前该站为补充发现源：失败时 tender 为 `degraded`；仅当陕西公共
  资源及采购与招标官方等价覆盖组均完整、当日命中均有正文核验、且回执写出受限来源 ID 时，
  才可发布，并必须在客户页写明“已完成扫描，来源受限”；不得绕过验证码；
- 必需来源覆盖不全、正文未取得或关键字段不确定时，对应栏目失败关闭；补充来源受限
  只触发栏目降级。
- MA 回执区分 `candidateOnScanDate` 与 `eventOnScanDate`：前者是待人工核验的
  当日候选，后者必须有同日、原文核验通过且实际写入正式事件库的 imported/updated
  事项。候选本身绝不能触发正式当日事件标志。

可控实扫可用 `refresh_tender_events.py --max-queries 1`，但该参数只用于诊断证据，
会强制产生不完整回执，禁止进入发布。正式运行不得传此参数。

客户端现有三条 V2 自动化均已切换到该契约：

- `v2-2`：工作日 05:30 全量；
- `v2-12-00`：工作日 12:00，listed/private 可做真实增量，MA/tender 当前仍按同日完整范围；
- `v2-17-00`：工作日 17:00，listed/private 可做真实增量或补偿，MA/tender 当前仍按同日完整范围。

三条任务不得在统一入口之外再次运行 MA/tender/SOE，也不得用
`record_channel_scan.py` 人工覆盖专用回执。

私募工作日使用 `--scan-mode daily` 复用上一成功年度基线，只核验当日新增与注销；
周末执行 `weekly` 年度一致性复核，每月1日执行 `monthly` 完整回溯。没有可用基线时
自动回退全量，禁止用缺失基线生成增量结论。

### MA / tender 审计产物

每次运行分别产生：

- `v2/data/source/<channel>/raw/raw-YYYY-MM-DD-SLOT.json`
- `v2/data/source/<channel>/candidates/candidates-YYYY-MM-DD-SLOT.json`
- `v2/data/source/<channel>/exclusions/excluded-YYYY-MM-DD-SLOT.json`
- `v2/data/source/<channel>/scans/scan-YYYY-MM-DD-SLOT.json`

回执记录 scanDate、slot、起止时间、各来源状态和失败原因、检索词/覆盖范围、
raw/候选/入库/排除数量、输入哈希、事件库输出哈希、最新真实事件日期及全部证据文件哈希。
每个列表适配器还记录请求 URL/参数、页数、日期边界、响应哈希和详情核验数量；
`external_blocked` 与代码未实现是不同状态，仓库配置禁止再出现
`registry_uncovered`/`health_probe_only`。
同一 MA 项目保留既有 `maProjectId`，后续正式进展只追加 `milestones/sourceRecords`；
tender 以规范化项目指纹合并不同阶段，重复运行不重复追加。

## 单一 V2 客户发布

V2 是唯一客户网页、网页归档、日图和 IMA 上传系统。旧版本不参与任何每日检索、渲染、
上传或发布，也不作为 V2 的运行时输入。

## 发布边界

发布只更新 gh-pages 的 `v2/` 运行白名单：六个页面、`assets/`、生产数据、构建版本、
栏目日图归档索引和 `archive/daily/` 图片。发布脚本会删除线上遗留的
`v2/images/`、`v2/share/` 和分享图清单。脚本、测试、文档和本地运行记录均不进入发布
提交；带日图的发布还逐张校验线上图片 HTTP 状态和 SHA-256。
