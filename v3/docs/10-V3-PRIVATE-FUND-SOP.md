# V3 证券私募情报台 SOP

版本：0.2  
生效日期：2026-07-22  
适用范围：陕西属地及经人工确认的陕西强关联私募证券投资基金管理人、人员、产品与公开关系

## 1. 目标

证券私募频道回答六个问题：

1. 本次新增备案了什么产品。
2. 哪20家管理人公开信息活跃度最高，排名如何复算。
3. 前20管理人的高管、员工数和公开履历是否变化。
4. 管理人与哪些券商存在 AMAC 公示的托管关系。
5. 哪些管理人出现疑似重新活跃信号。
6. 哪些管理人注册地址和办公地异省，是否出现可验证的地址变化。

## 2. 数据源与边界

主源为中国证券投资基金业协会信息公示系统：

- 管理人列表和详情页。
- 私募基金公示和托管人字段。
- 已注销管理人公示。

V3 只读继承 V1 原始 JSON，不修改 V1。管理规模区间、高管、员工数、履历和出资人必须逐家回源详情页。

观察主体分为两层，均按重要对象进入产品、人员和托管关系监测，但统计必须分列：

- `PF1`：AMAC当前公示注册地或办公地在陕西省，当前基线82家。
- `PF2`：注册地、办公地均不在陕西，但官方材料确认在陕西设有实质办公分部、历史主体或持续经营平台；逐家人工准入，当前基线1家。

当前 `PF2` 仅纳入深圳抱朴容易私募证券基金管理有限公司（P1020607）。陕西泰发祥集团官网确认其总部在深圳，并在西安、上海设有分部，因此作为陕西强关联重要观察对象，不计入82家属地管理人。

仅因董事长、法定代表人或总经理曾在西安学习、任职的管理人不纳入；陕西籍、校友、一般项目合作和产品名称相似也不构成准入。规则与名单以 `config/private-fund-universe.json` 为准。

公开托管关系只说明某只备案产品披露的托管人，不等于全部券商合作、代销、交易或 PB 关系。社会关系和券商合作不得由姓名、履历或托管人字段过度推断。

## 3. 运行输入与命令

输入文件：

- `v1/陕西省证券私募日报v1/data/security-private-fund-daily-YYYY-MM-DD.json`
- 上一可比日期的同名 JSON。

生成命令：

```bash
.venv/bin/python v3/scripts/build_private_fund_snapshot.py \
  --date YYYY-MM-DD \
  --previous-date YYYY-MM-DD
node v3/scripts/validate_private_fund.mjs
```

输出：

- `data/private-fund/snapshots/YYYY-MM-DD.json`
- `data/private-fund/snapshots/latest.json`

同日重跑默认复用已成功回源的详情。只有需要重新抓取 AMAC 详情时使用 `--refresh-details`。

## 4. 差异规则

新备案按唯一 `fundNo` 比较当前和上一期，不按产品名称模糊匹配。全年累计列表不得包装成本次新增。

人员差异仅在上一期存在 V3 详情快照时计算：

- 高管新增：`name + role` 当前存在、上一期不存在。
- 高管减少：`name + role` 上一期存在、当前不存在。
- 员工变化：全职员工数或基金从业人数发生变化。

首期快照固定为 `baseline_created`，`personnelChanges` 必须为空。不得根据当前履历倒推历史离任、跳槽或迁移。

## 5. 观察池与活跃前20

公式固定为：

```text
min(存量产品数, 40) * 2
+ 年内备案数 * 10
+ 备案新鲜度（30天内12分、90天内6分）
```

排序依次使用活跃分、年内备案数、存量产品数、管理人名称。该分数只用于公开信息活跃度排序，不代表管理规模、投资能力、收益或风险水平。

排序范围为 `PF1 + PF2` 全部重要观察对象。`PF2` 年内产品从全国证券私募产品公示中按管理人登记编号/标准名称提取，不得因为注册办公地不在陕西而漏检。

每一名必须展示可复算的分数组成，并链接 AMAC 管理人详情页。

## 6. 疑似重新活跃

满足“上一期年内备案为0、本期出现首只年内备案”时，只能标记 `reactivationCandidate=true`。

确认“壳体重新启用”至少还需要一项独立证据：

- 更长历史窗口显示长期无产品后重新备案。
- 高管、实控人或主要出资人发生可验证变化。
- 工商状态、注册地址或办公地址发生可验证变化。

证据不足时页面必须使用“重新活跃候选”，不得写“已启用”“借壳”或“重启完成”。

## 7. 地址与迁移

注册地址与办公地异省只记为 `location_observation`。没有前后快照地址变化时，不得写“迁入陕西”或“迁出陕西”。

只有同一管理人前后快照出现省份变化，且 AMAC 或工商原文可回溯时，才可建立迁入/迁出候选；确认结论仍需双源复核。

## 8. RM Dashboard 业务分类

私募线索统一映射六类：

- `product_account_opening`：产品开户。
- `custody_outsourcing`：托管外包。
- `special_mandate_reduction`：特委减持。
- `otc_derivatives`：场外衍生品。
- `b_share_funding`：B份额。
- `performance_allocation`：业绩切分。

产品新备案可以提示产品开户和托管外包适配，但不能写成业务已落地。

## 9. 发布检查

- 前20登记编号和排名唯一，排名连续。
- 观察池数量等于 `PF1 + PF2`，当前应为 `82 + 1 = 83`；抱朴容易必须标记为 `PF2/important`。
- PF2只允许人工配置，不得由人员履历关键词自动扩展。
- 活跃分等于披露的分数组成。
- 人员覆盖数与成功详情数一致。
- 每个新增产品有基金编号、备案日期和 AMAC 链接。
- 首期基线没有人员变化结论。
- 异地地址没有迁入迁出结论。
- 桌面和390px手机无整页横向溢出。
- 控制台无错误。

任何规则失败时停止更新私募页面，保留上一成功 `latest.json` 并记录降级原因。
