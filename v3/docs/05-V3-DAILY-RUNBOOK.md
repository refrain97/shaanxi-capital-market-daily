# V3 每日两次更新运行手册

版本：0.4  
生效日期：2026-07-11  
当前实现状态：两次日报统一入口尚未开发；招投标小时扫描器已可独立运行

## 1. 重要说明

本手册是后续自动化和人工运行的执行依据。招投标扫描器已实现，其余统一命令仍不得假定存在。

V1 在 V3 研发期间继续独立运行。运行 V3 不得覆盖、移动或重写 V1 文件。

## 2. 上下文恢复

开始任何 V3 运行或开发前：

1. 阅读 `v3/README.md`。
2. 阅读总 SOP、质量闸门、数据源 SOP、Provider 配置和数据契约。
3. 阅读本次涉及的频道 SOP。
4. 阅读决策日志最后一条记录。
5. 查看路线图和当前实现状态。

如果聊天内容与文档冲突，以文档权威顺序为准；用户刚确认的新要求应先写入文档再执行。

## 3. 运行输入

每次运行必须明确：

| 输入 | 说明 |
|---|---|
| `date` | 报告日期，Asia/Shanghai |
| `slot` | `morning` 或 `closing` |
| `dataCutoffAt` | 本次数据截止时间 |
| `previousSnapshotId` | 上一成功快照 |
| `sourcePlan` | 本次应运行的来源清单 |
| `providerPlan` | 本次 Wind/iFinD 职责、指定路径和真实探针清单 |
| `manualOverrides` | 经记录的人工修正或强制回溯范围 |

缺少日期、快照类型或上一成功状态时不得启动正式运行。

## 4. 上午更新清单

### 4.1 运行前

- [ ] 确认报告日期、交易日和节假日窗口。
- [ ] 检查上一盘后快照和未完成待核验项。
- [ ] 检查 L1/L2/L3 公司池、主体池、排除名单、别名表和来源配置版本。
- [ ] 检查 CNINFO、AMAC、招投标平台、国企官网等来源健康。
- [ ] 读取 `config/data-providers.json`，从指定 Codex 路径分别真实调用 Wind 和 iFinD 探针。
- [ ] 记录 Provider ID、路径标识、状态、耗时、错误码、数据时点和影响频道；不得记录密钥。
- [ ] 若发现其他同名 skill 副本，不自动切换；只有独立探针通过并显式登记后才可使用。

### 4.2 采集

- [ ] 上市公司按 L1/L2/L3 主体池检索上一收盘后至当前公告；A股查 CNINFO，港股查港股公告源。
- [ ] 招投标优先抓公告、采购、遴选、征集栏目。
- [ ] 私募抓取机构、注销、产品和人员快照。
- [ ] 股权融资抓取辅导、融资和产业基金新增。
- [ ] 收并购复核最近 3-7 天及行动中事件。
- [ ] 国企雷达抓取主体池新增页面。

### 4.3 处理

- [ ] 原始记录落盘并生成来源运行记录。
- [ ] 实体匹配和别名归一。
- [ ] 事件去重、合并和时间线更新。
- [ ] 核验公告时间、发现时间和截止时间。
- [ ] 生成今日新增、行动窗口、风险和待核验信号。
- [ ] 对满足条件的信号生成业务线索。

### 4.4 发布前

- [ ] 生成 `morning` 快照。
- [ ] 运行全部质量闸门。
- [ ] 核对首页 KPI 与下钻明细。
- [ ] 检查未来 30 天行动日历。
- [ ] 检查桌面和移动端。
- [ ] 发布并验证线上快照日期和关键链接。

## 5. 盘后更新清单

### 5.1 运行前

- [ ] 读取当日上午快照和质量结果。
- [ ] 列出上午待核验、高优先级和即将截止事项。
- [ ] 确认日内新增来源范围。
- [ ] 重新执行 Wind 和 iFinD 真实探针；上午成功状态不得沿用为盘后状态。

### 5.2 采集与核验

- [ ] 补抓日内上市公司公告及正文。
- [ ] 更新招投标变更、延期、候选和结果。
- [ ] 更新私募和融资延迟披露。
- [ ] 更新并购、国企和主体事件进展。
- [ ] 完成上午关键事项正文回源和数字复核。

### 5.3 数据整理

- [ ] 更新财务、产品、人员、融资、并购和招投标年度表。
- [ ] 计算本次相对上午快照的变化。
- [ ] 更新线索状态和明日复核节点。
- [ ] 生成需要的漏检复盘。

### 5.4 发布前

- [ ] 生成 `closing` 快照并关联上午快照。
- [ ] 验证同一事件没有重复创建。
- [ ] 验证年度 KPI 没有通过快照相加计算。
- [ ] 运行全部质量闸门。
- [ ] 发布并验证首页、年度页、详情页和证据页。

## 6. 招投标小时扫描

人工或自动化每次执行：

```bash
node v3/scripts/scan_tender_sources.mjs
node v3/scripts/validate_tender_runtime.mjs
node v3/scripts/validate_tender_classifier.mjs
node v3/scripts/validate_data.mjs
```

执行后必须检查：

- `data/tender/scans/latest.json` 的来源成功/失败、新增、变化、有效机会和待复核数量。
- `data/tender/alerts/latest.json` 只包含截止仍有效、资格适配且已回源项目。
- 第二轮无变化时 `newCount=0`、`changedCount=0`，不得重复提醒。
- 单站失败保留降级状态；其他来源继续，但不得声称全源成功。
- 自动化 `v3-60` 应保持 `ACTIVE`；页面必须显示真实来源通过数，单站失败时显示降级，不得显示全源成功。

## 7. 无新增运行

当全部频道无实质新增时：

- 仍保存来源运行记录和健康状态。
- 生成引用为空的快照差异，写明本次检查无新增。
- 保留仍在行动窗口的旧事件引用。
- 年度事件数不变。
- 不复制上一期内容，不创建虚假新事件，不上传重复长图。

## 8. 失败与降级

### 8.1 单一非关键来源失败

- 记录失败。
- 使用其他权威来源继续。
- 相关对象标记 REVIEW 或待核验。

### 8.2 关键来源失败

例如 CNINFO 主检索、AMAC 主接口、招投标公告源整体失败：

- 不得写该频道完成完整更新。
- 可发布 `DEGRADED` 快照，首页展示来源异常。
- 不得使用旧数据冒充本次结果。
- 安排重试和恢复后补跑。

### 8.3 Wind/iFinD 失败或冲突

- Wind 默认路径失败时不得静默切到 `~/.agents/skills/wind-mcp-skill` 或其他同名副本。
- 单一 Provider 失败时标记 `DEGRADED`；L2、持股和 A+H 等需双源核验的变更进入 REVIEW。
- 两个 Provider 都失败时冻结 L2 名单、持股比例和供应商派生指标，保留最后核验值并标记 `stale`。
- Wind/iFinD 关键字段冲突时保留双方值与数据时点，回到官方来源；未解决前不得进入正式 KPI。
- Provider 恢复后补跑受影响范围，不只恢复页面状态。

### 8.4 质量闸门失败

- 保存草稿和错误列表。
- 修正数据对象，不直接手改最终 HTML 掩盖问题。
- 重新运行受影响频道和全局统计验证。
- 通过后才发布正式快照。

### 8.5 发布失败

- 保持上一成功版本在线。
- 记录构建、网络或链接错误。
- 不回复“已发布”。
- 修复后重新验证线上日期、页面和关键链接。

## 9. 运行产物

每次成功运行至少产生：

- 来源运行记录。
- 原始记录索引。
- 更新后的实体、事件、信号和线索对象。
- 上午或盘后快照。
- 质量结果。
- 静态站或应用构建产物。
- 线上验证结果。

只有页面变化而主数据无变化，不算有效内容更新。

## 10. 运行报告模板

```markdown
# V3 运行报告｜YYYY-MM-DD｜morning/closing

- 运行状态：PASS / PASS_WITH_REVIEW / DEGRADED / FAIL
- 数据截止：YYYY-MM-DD HH:mm Asia/Shanghai
- 上一快照：snapshot-id
- 来源：成功 X，失败 X，降级 X
- Provider：wind_codex PASS/DEGRADED/FAIL；ifind_codex PASS/DEGRADED/FAIL
- Provider 路径：仅记录配置 ID；不得记录密钥或鉴权内容
- 事件：新增 X，进展 X，回溯 X，排除 X
- 信号：重点 X，行动窗口 X，风险 X，待核验 X
- 线索：新增 X，状态更新 X
- 质量：BLOCK X，REVIEW X
- 发布：本地通过 / 线上已验证 / 未确认
- 关键文件或版本：...
```

## 11. 未来统一命令契约

实现自动化时建议提供一个统一入口，但在脚本真正存在前不得执行下列示意命令：

```text
run_v3 --date YYYY-MM-DD --slot morning
run_v3 --date YYYY-MM-DD --slot closing
run_v3 --date YYYY-MM-DD --slot closing --publish
```

统一入口应负责调度采集、合并、验证、渲染和发布，不允许跳过质量闸门直接发布。
