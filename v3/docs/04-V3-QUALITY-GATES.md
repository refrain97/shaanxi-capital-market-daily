# V3 强约束与质量闸门

版本：0.9  
生效日期：2026-07-12  
权威级别：最高  
原则：阻断项不通过，不得发布正式 V3 快照

## 1. 执行级别

| 级别 | 含义 | 动作 |
|---|---|---|
| `BLOCK` | 真实性、时间、去重、统计或发布存在实质问题 | 停止正式发布 |
| `REVIEW` | 可能影响质量，需要人工复核 | 可生成草稿，不得静默忽略 |
| `INFO` | 运行状态或改进提示 | 记录即可 |

验证器实现后，每条规则必须有稳定规则 ID、错误对象 ID 和可读错误信息。

## 2. 来源与完整性

| 规则 ID | 级别 | 规则 |
|---|---|---|
| `SRC-001` | BLOCK | 正式事件必须至少关联一个可访问的来源记录 |
| `SRC-002` | BLOCK | `discovery_only` 来源不能单独把候选升级为已确认事件 |
| `SRC-003` | BLOCK | 上市公司关键数字必须有公告正文或 PDF 证据 |
| `SRC-004` | BLOCK | 招投标行动机会必须有公告正文或官方公告页依据 |
| `SRC-005` | BLOCK | AMAC 来源失败时不得沿用旧数据并写成本次成功更新 |
| `SRC-006` | REVIEW | 关键来源缺失发布时间、正文或附件 |
| `SRC-007` | REVIEW | 同一关键事实的多个来源存在冲突 |

## 3. 实体与去重

| 规则 ID | 级别 | 规则 |
|---|---|---|
| `ENT-001` | BLOCK | 正式事件必须有可解析的 `primaryEntityId` |
| `ENT-002` | BLOCK | 主题词、事项词和产品词不得写入公司实体字段 |
| `ENT-003` | BLOCK | 同一证券代码、AMAC 编号、基金编号或项目编号不得映射多个活动实体 |
| `DEDUP-001` | BLOCK | 同一 `eventKey` 不得存在多个主事件 |
| `DEDUP-002` | BLOCK | 同一 `eventId` 同一时点不得生成多个主信号 |
| `DEDUP-003` | BLOCK | 公司、股东、子公司或业务主题换名后不得重复展示同一事项 |
| `DEDUP-004` | REVIEW | 相似事件标题和数字高度重合但事件键不同 |

## 4. 时间与新颖性

| 规则 ID | 级别 | 规则 |
|---|---|---|

| `TIME-002` | BLOCK | 历史事项当天补录必须标记 `backfill`，不能标记本日发生 |

| `TIME-006` | REVIEW | 来源发布时间晚于抓取时间或关键时间顺序异常 |

## 7. 频道特有阻断规则

### 7.1 上市公司

- `LST-001 BLOCK`：未完成逐公司公告检索或公司池版本不明。
- `LST-002 BLOCK`：高价值公告没有原文证据。
- `LST-003 BLOCK`：年报季报关键财务数据没有报告期和单位。
- `LST-004 BLOCK`：跟踪项重新创建事件，而不是引用原事件。
- `LST-005 BLOCK`：主体没有 `L1/L2/L3` 层级或纳入依据。
- `LST-006 BLOCK`：A+H 同一发行人被重复建立主体。
- `LST-007 BLOCK`：L3 将持股比例等于10%误判为大于10%。
- `LST-008 BLOCK`：比亚迪或海格通信被纳入当前 L3 扩展池。
- `LST-009 REVIEW`：港股或关联主体池超过规定周期未复核。
- `LST-010 BLOCK`：公告数、发布公司数或有效事项数不能与明细下钻对账。
- `LST-011 BLOCK`：同一公告进入多个事项，或事项来源没有挂回唯一事件。
- `LST-012 BLOCK`：完整日报事项缺少有效性判断、RM 分类或纳入原因。
- `LST-013 BLOCK`：一级业务、二级标签、业务重点或跟进对象与统一配置不一致。
- `LST-014 BLOCK`：内容重要性被直接等同于业务重点，或非确认标签被标成业务重点。
- `LST-015 BLOCK`：股份回购没有归入“资本运作/股份回购”重点标签。
- `LST-016 BLOCK`：激励股份回购注销被误归为资本运作，而不是“激励与员工/回购注销”。
- `LST-017 BLOCK`：完整主体池总数不是L1/L2/L3明细之和，或同一证券代码跨层重复。
- `LST-018 BLOCK`：页面把实际返回主体数、辖区A股数或旧口径117家冒充当前完整观察池。
- `LST-019 BLOCK`：当前基线下L2不是14家、L3不是11家，或明确排除对象进入活动L3。
- `LST-020 BLOCK`：仅低比例财务持股、信托/基金产品持股或自然人履历触发自动纳入。
- `FIN-001 BLOCK`：`financialReportId` 不唯一。
- `FIN-002 BLOCK`：财务记录没有引用上市公司事件和匹配主体。
- `FIN-003 BLOCK`：财务记录缺少可访问的原始公告来源。
- `FIN-004 BLOCK`：利润区间上下界倒置或由模型推断未披露数值。
- `FIN-005 BLOCK`：财务记录缺少报告期、披露类型或币种；不同口径被直接合计。

### 7.2 证券私募

- `PF-001 BLOCK`：注销机构类型未确认。
- `PF-002 BLOCK`：注册地和办公地混为同一口径。
- `PF-003 BLOCK`：接口限额数据被描述为完整累计。
- `PF-004 BLOCK`：没有差异却把全年列表包装成本次新增。
- `PF-005 BLOCK`：活跃前20分数不能由披露的分数组成复算，或排名/登记编号重复。
- `PF-006 BLOCK`：人员详情缺少AMAC原文，或人员覆盖数与明细不一致。
- `PF-007 BLOCK`：首期人员基线输出新增、离任或跳槽结论。
- `PF-008 BLOCK`：公开托管人字段被描述为全部券商合作关系。
- `PF-009 BLOCK`：仅因年内首只备案就写成壳体已重新启用。
- `PF-010 BLOCK`：仅因注册地址和办公地异省就写成迁入或迁出。
- `PF-011 BLOCK`：新备案产品缺少唯一基金编号、备案日期或AMAC原文。

### 7.3 股权融资

- `EQ-001 BLOCK`：媒体传闻直接写成已完成融资。
- `EQ-002 BLOCK`：融资金额、投资方或轮次由模型推断补写。
- `EQ-003 REVIEW`：工商变化与官方披露不一致。
- `EQ-004 BLOCK`：融资记录缺少金额文本、投资方、日期或可访问来源。
- `EQ-005 BLOCK`：B/C档只有总量依据时自行生成企业明细。
- `EQ-006 BLOCK`：已上市主体仍显示为聆讯中、申报中或上市后备。

### 7.4 收并购

- `MA-001 BLOCK`：同一交易进展重复计为新案例。
- `MA-002 BLOCK`：未披露交易金额或估值被自行估算。
- `MA-003 BLOCK`：累计案例来自写死页面而不是事件库。
- `MA-004 BLOCK`：并购项目缺少唯一项目ID、阶段或时间线。
- `MA-005 BLOCK`：里程碑日期倒序、阶段非法或引用不存在的来源。
- `MA-006 BLOCK`：待补官方来源的历史项目显示为已回源。
- `MA-007 BLOCK`：项目阶段统计、官方来源数或待补来源数不能与明细对账。

### 7.5 关系与年度统计

- `REL-001 BLOCK`：关系边引用不存在的起点或终点。
- `REL-002 BLOCK`：关系边缺少关系类型、证据类型或唯一ID。
- `REL-003 BLOCK`：无证据的人物、股权、托管、投资或并购关系进入关系层。
- `REL-004 BLOCK`：非HTTPS原文被标记为可点击证据。
- `STAT-006 BLOCK`：不同业务口径相加生成无定义的年度总数。
- `STAT-007 BLOCK`：月序列不足12个月、顺序错误或受限样本冒充完整分布。

### 7.6 生产运行

- `RUN-001 BLOCK`：运行时点覆盖或改写源数据时点。
- `RUN-002 BLOCK`：存在过期输入却输出 `PASS` 或描述为今日新数据。
- `RUN-003 BLOCK`：任一步骤失败仍描述为发布成功。
- `RUN-004 BLOCK`：上午和盘后运行使用同一运行ID或并发写入。
- `RUN-005 BLOCK`：V3运行修改V1/V2目录或重复承担每小时招投标扫描。

### 7.5 招投标

- `TEN-001 BLOCK`：新增机会不是在公告阶段发现。
- `TEN-002 BLOCK`：缺少投标截止日且仍标为可投。
- `TEN-003 BLOCK`：候选、中标或成交结果计入新增机会。
- `TEN-004 BLOCK`：同一项目结果另建新项目。
- `TEN-005 REVIEW`：首次发现已到结果阶段但没有漏检复盘。
- `TEN-010 BLOCK`：扫描频率不在30至60分钟，或监控状态与来源注册表不一致。
- `TEN-011 BLOCK`：非招投标事件、非行动窗口或截止已过仍进入有效机会区。
- `TEN-012 BLOCK`：项目没有引用唯一事件和匹配采购主体。
- `TEN-013 BLOCK`：候选/结果阶段或首次发现已截止仍生成即时机会提醒。
- `TEN-014 BLOCK`：漏检项目没有进入 `miss_review`。
- `TEN-015 BLOCK`：结果线索进入 `active_opportunity`。
- `TEN-016 BLOCK`：搜索摘要 `discovery_only` 直接进入机会区。
- `TEN-017 BLOCK`：资格排除项目仍生成提醒。
- `TEN-018 BLOCK`：扫描运行 ID 重复或缺少运行记录。
- `TEN-019 BLOCK`：来源注册表过窄、使用非 HTTPS 或扫描间隔非法。
- `TEN-RUN-001 BLOCK`：来源注册表中的来源缺少本轮运行记录或重复运行。
- `TEN-RUN-002 BLOCK`：实时扫描记录 ID 缺失或重复。
- `TEN-RUN-003 BLOCK`：实时记录缺少内容指纹或 HTTPS 原文地址。
- `TEN-RUN-004 BLOCK`：即时机会的阶段、资格、来源或剩余时间不满足准入条件。
- `TEN-RUN-005 BLOCK`：候选、结果、合同、结束或终止阶段进入机会区。
- `TEN-RUN-006 BLOCK`：来源、记录、机会、待核验、历史或排除统计不能与明细对账。
- `TEN-RUN-007 BLOCK`：新增/变化列表引用未知记录或存在重复 ID。

### 7.6 国企雷达

- `SOE-001 BLOCK`：同一新闻在今日重点与分类栏重复长写。
- `SOE-002 BLOCK`：7 日窗口旧事件标成本日新增。
- `SOE-003 REVIEW`：高频宣传稿挤占高价值资本和项目事件。

## 8. 收藏与长期跟踪

| 规则 ID | 级别 | 规则 |
|---|---|---|
| `WATCH-001` | BLOCK | `watchId` 必须唯一，同一 `eventId` 不得建立多个跟踪项 |
| `WATCH-002` | BLOCK | `eventId` 必须引用已存在事件 |
| `WATCH-003` | BLOCK | `entityId` 必须引用已存在主体，且与事件主主体一致 |
| `WATCH-004` | BLOCK | `watchStatus` 必须属于规定状态枚举 |
| `WATCH-005` | BLOCK | 活动状态必须有合法的 `nextReviewAt` |
| `WATCH-006` | BLOCK | `stateHistory` 不得为空，末项状态必须等于当前 `watchStatus` |
| `WATCH-007` | BLOCK | `createdAt`、`updatedAt` 必须合法，且更新时间不得早于创建时间 |

工作备注只能写入 `watchItem.note`，页面按独立区域渲染；不得覆盖 `event`、`evidence`、来源证据或原始摘要字段。

## 11. 漏检复盘

以下情况必须生成漏检复盘：

- 招投标首次发现已到候选或结果阶段。
- 上市公司重要事项在后续公告才被识别。
- 私募变更在多次快照后才发现。
- 并购或融资事项已出现重大进展但事件库没有前序记录。

复盘至少记录：

- 原始首次公开时间和实际发现时间。
- 应该命中的来源、主体词、事件词或公告类型。
- 漏检原因：来源失败、规则缺失、解析失败、实体未映射或人工判断遗漏。
- 修复动作和对应规则/测试。

同一原因连续出现两次时，必须升级为阻断项或新增自动测试。

## 12. 发布判定

质量结果固定为：

- `PASS`：无 BLOCK，正式发布。
- `PASS_WITH_REVIEW`：无 BLOCK，有 REVIEW，发布并展示质量提示。
- `DEGRADED`：关键来源失败但允许发布明确降级页，不得声称完整。
- `FAIL`：存在 BLOCK，停止正式发布。

运行记录必须保存所有触发规则、对象 ID、处理人和处理结果。
