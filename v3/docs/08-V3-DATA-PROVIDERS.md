# V3 金融数据源与调用约束 SOP

版本：0.1  
生效日期：2026-07-11  
权威级别：数据源调用与降级依据

## 1. 目的

本 SOP 解决“能力看似已经配置，但实际运行调用了错误路径或失效接口”的问题。V3 不以 skill 文件存在、环境变量名称存在或历史上调用成功作为数据源健康依据，只承认本班次真实请求的结果。

非敏感机器配置见 `config/data-providers.json`。密钥、Token、Cookie 和完整鉴权响应不得写入 V3 目录、运行报告或发布页面。

## 3. 来源职责

| 来源层 | 职责 | 可否单独确认正式事实 |
|---|---|---|
| 官方披露 | CNINFO、交易所、港交所、AMAC、监管、采购与招标公告正文等原始证据 | 可以，且关键事实最终以其为准 |
| Wind | 主体池、证券代码、公司基础信息、财务与股东等结构化数据 | 可形成结构化候选；正式事件关键事实仍需官方证据 |
| iFinD | 独立交叉核验、公告资讯发现、主体与股东数据补充 | 可形成结构化候选；与 Wind 冲突时不得静默裁决 |
| 搜索与聚合 | 发现网页和补充检索词 | 不可以，只能进入候选池 |

Wind 和 iFinD 是数据服务商，不替代公告正文。尤其是公告时间、投标截止日、交易金额、财务报告期和事件状态，必须保存可回溯的官方证据。

## 4. 每班次真实探针

上午版和盘后版开始时，必须读取 `config/data-providers.json`，对本班次计划使用的每个 Provider 发起一次低成本、可解析的真实查询。

探针要求：

1. 必须走配置中的实际根目录和入口，不能只检查目录、密钥文件或环境变量。
2. 必须验证鉴权成功、HTTP/协议成功和业务结果可解析。
3. 探针查询只验证连通性，不得把探针结果写入当日业务事件。
4. 每个班次分别执行；上午成功不能替代盘后探针。
5. 备用 skill 根目录必须独立探针通过后才可显式切换，不允许按同名目录自动回退。

健康状态固定为：

- `PASS`：鉴权、请求和结果解析均成功。
- `DEGRADED`：可调用，但部分工具、字段或时效性受限。
- `FAIL_AUTH`：密钥、权限或鉴权失败。
- `FAIL_NETWORK`：网络、DNS、TLS 或服务不可达。
- `FAIL_QUOTA`：限额、频控或额度不足。
- `FAIL_SCHEMA`：返回成功但结构不符合契约，无法安全解析。

## 5. 运行记录

每次探针只记录以下非敏感字段：

```json
{
  "providerId": "wind_codex",
  "skillRootId": "codex_local",
  "status": "PASS",
  "checkedAt": "2026-07-11T09:00:00+08:00",
  "latencyMs": 0,
  "errorCode": null,
  "dataAsOf": null
}
```

不得记录：密钥值、Token、Authorization Header、Cookie、完整鉴权响应、包含凭据的命令行或截图。

## 6. 双源核验与冲突

以下事项优先执行 Wind + iFinD 交叉核验，并回到官方来源定稿：

- 陕西港股主体池的初建和季度复核。
- L3 持股比例及其是否严格大于 10%。
- A+H 代码归一、上市状态、退市和迁址。
- 关键财务指标、股本和股东变动存在口径疑问时。

冲突处理顺序：

1. 先比较证券代码、报告期、公告日期、币种、合并口径和数据更新时间。
2. 能回到官方披露的，以官方披露为最终事实并保存证据。
3. Wind 与 iFinD 仍冲突且官方材料暂不可得时，字段设为 `conflict`，保留两边值和各自 `dataAsOf`。
4. 冲突字段不得进入正式 KPI、行动窗口判断或“已确认”表述。

## 7. 失败与降级

| 情况 | 处理 |
|---|---|
| Wind 失败、iFinD 成功 | 标记数据服务降级；可继续发现和交叉核验，Wind 专属派生字段暂停刷新 |
| iFinD 失败、Wind 成功 | 标记数据服务降级；关键名单和持股变更缺少双源核验时进入 REVIEW |
| 两者都失败 | 冻结 L2 名单、持股比例和依赖供应商的派生指标；保留最后核验值并明确 `stale`，不得写成当日新增 |
| 官方源失败 | 供应商数据只能形成候选；关键事件不得升级为正式确认 |
| 配置路径失败但发现另一同名副本 | 不自动切换；先独立探针并在运行记录中显式登记路径变更 |

Provider 恢复后必须补跑受影响范围，并更新 `lastCheckedAt`、`dataAsOf` 和质量结果。

## 8. 密钥与配置纪律

- V3 仓库只保存 Provider ID、调用路径、职责和无敏感探针参数。
- 不移动、不复制、不读取明文密钥来“统一配置”。
- 不把本机可用状态描述为全局可用；当前 Wind 仅确认 Codex 本地路径可用。
- 如果以后建立全局配置，必须分别验证新路径和旧路径，并更新本 SOP、配置文件和决策日志。
- 任何密钥泄露迹象触发 `PROV-003 BLOCK`，停止发布并先处理凭据轮换。

## 9. 页面质量呈现

质量中心应显示 Provider ID、状态、检查时间、数据时点和受影响频道，不显示本机绝对密钥路径或任何凭据。对外页面使用“数据源正常/降级/待恢复”等可读状态，详情页保留内部审计 ID。

## 10. 完成定义

数据源体检只有同时满足以下条件才算完成：

- 本班次计划使用的 Provider 已真实调用。
- 调用路径与配置一致。
- 状态和影响范围已落运行记录。
- 冲突、陈旧和降级数据没有被包装成当日新事实。
- 运行产物和日志中没有敏感凭据。
