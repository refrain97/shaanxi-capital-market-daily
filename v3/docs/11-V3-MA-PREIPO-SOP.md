# V3 并购与拟上市融资 SOP

版本：0.1  
更新日期：2026-07-12

## 1. 目标

- 并购以唯一项目持续追加进展，不把同一交易的公告、问询、批准和交割拆成重复案例。
- 拟上市企业以省级后备名录为母池，优先维护 A 档、辅导中、申报中和已上市毕业主体。
- 融资金额、轮次和投资方只记录可回源事实，不用新闻传闻或模型推断补齐。

## 2. 并购项目流程

1. 读取 V1 历史案例和当日公告，只作为候选输入。
2. 以交易主体、标的、交易方向和首次披露日期确定 `maProjectId`。
3. 已存在项目只追加 `milestones` 并更新阶段、最新节点和下一步动作。
4. 阶段只允许：`planning`、`signed_or_approved`、`in_progress`、`completed`、`terminated`。
5. 每个里程碑必须保存日期、标签、阶段和来源引用。
6. 未逐条补齐官方公告的 V1 历史项目固定为 `needs_source_backfill`，不得包装为已核验。

## 3. 拟上市企业流程

1. 省级上市后备名录保存发行日期、文号、原始附件和 A/B/C 总量。
2. 当前逐家建档只覆盖 A 档 80 家；B/C 档仅展示经核验总量，不生成虚构明细。
3. 企业发生融资、辅导、申报、问询、聆讯、上市或终止时，追加同一主体时间线。
4. 上市后状态改为 `listed_*` 并保留“毕业”档案，不继续显示为上市后备。
5. 并购涉及拟上市主体时，用同一企业名称和项目 ID 形成进展关联。

## 4. 融资记录流程

- 必填：企业、轮次、金额文本、投资方、披露日期、来源 URL、来源质量和核验状态。
- 金额未披露时保留“未披露”，不得估算。
- 工商股东变化只作为待核验候选，不直接写成融资完成。
- IPO 基石投资与普通私募融资分开标注。

## 5. 当前运行

```bash
.venv/bin/python v3/scripts/build_phase5_data.py
node v3/scripts/validate_phase5.mjs
```

输出：

- `data/ma-projects/latest.json`：25 个并购项目及时间线。
- `data/pre-ipo/latest.json`：530 家总盘、A 档 80 家明细、上市毕业主体和已核验融资。
- `schemas/ma-projects.schema.json`、`schemas/pre-ipo.schema.json`：结构约束。

## 6. 当前边界

- 25 个并购项目中 2 个已关联官方来源，23 个历史项目待逐条回源。
- 530 家后备企业中当前仅 A 档 80 家完成逐家建档。
- 融资表当前只有 1 条已核验记录；空缺代表尚未核验，不代表企业没有融资。
