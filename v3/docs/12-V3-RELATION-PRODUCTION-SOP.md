# V3 关系、年度分析与生产运行 SOP

版本：0.1  
更新日期：2026-07-12

## 1. 统一关系层

- 关系节点来自现有实体、事件、私募管理人/人员/股东、产品/托管人、并购项目、拟上市企业和投资人。
- 每条边必须包含唯一 ID、起点、终点、关系类型和证据类型；有原文时保存 HTTPS 地址和日期。
- 当前关系类型：主体事件、任职高管、股东、管理产品、产品托管、关联并购、投资关系。
- 不从自然语言相似度自动生成股权、任职或合作关系；没有证据的视觉连线不得进入数据层。

生成与校验：

```bash
.venv/bin/python v3/scripts/build_phase6_data.py
node v3/scripts/validate_phase6.mjs
```

当前结果：266 个节点、128 条证据关系边。

## 2. 年度分析口径

- 上市日报、并购项目、私募管理人/产品、上市后备、融资和招投标扫描分别统计。
- 不把 530 家后备企业、81 条扫描记录、27 只产品和 25 个并购项目相加生成“总事件”。
- 事件累计只按唯一 `eventId`；快照、扫描轮次和同项目里程碑不重复计入。
- 证券私募月序列只展示进入 V3 差异记录的备案，不冒充全年27只的完整月度分布。

## 3. 两次日更入口

```bash
.venv/bin/python v3/scripts/run_v3.py --slot morning
.venv/bin/python v3/scripts/run_v3.py --slot midday
.venv/bin/python v3/scripts/run_v3.py --slot closing
```

运行器依次重建上市公司主体池、Phase 5/6数据并执行全部验证，其中上市公司业务分类和主体池各有独立验证器。当前共11个生成/验证步骤，每次运行保存不可变运行记录和对应 `latest-*.json`。

质量结果：

- `PASS`：全部验证通过，所有核心输入数据时点为运行当天。
- `PASS_WITH_STALE_INPUT`：验证通过，但至少一个输入不是当天数据。
- `FAIL`：任一生成或验证步骤失败，不得描述为成功发布。

运行时点绝不覆盖数据时点。当前上午、盘后实跑均为 `PASS_WITH_STALE_INPUT`，因为上市公司样例和私募快照仍为2026-07-10。

## 4. 自动化职责

- `v3`：每日03:30全量运行。
- `v3-2`：每日12:00午间更新。
- `v3-17`：每日17:00更新。
- 三次任务均先刷新招投标，再执行统一生成和质量校验。
- 原独立招投标任务 `v3-60` 停用，避免与统一运行并发写入。
- 页面继续保留上午/盘后主入口，午间更新作为独立运行记录保存。
- V1/V2目录和自动化保持不变，V3处于独立并行试运行。

## 5. 生产升级门槛

- 上市公司和私募适配器改为按运行日生成源快照，不再固定读取2026-07-10样例。
- 上午/盘后连续试运行，`STALE`、失败步骤和来源降级均可见。
- 页面数据日期、运行记录和自动化报告三者一致后，才可由“并行原型”升级为正式发布。
