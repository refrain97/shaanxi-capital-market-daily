# V3 频道工作台与长期跟踪蓝图

版本：0.1  
确认日期：2026-07-11  
状态：下一阶段产品与实施依据  
适用范围：V3 本地原型之后的频道深化、长期跟踪和生产化建设

## 1. 核心判断

V3 不能只解决“每天生成一份日报”，而要同时解决：

1. 快速、完整、准确地看到今天新增和变化。
2. 把真正重要的事件保存下来，持续跟踪到结果。
3. 把年报、季报、备案、人员、融资、并购和招投标转换为可比较的数据。
4. 让每条结论都能回到主体、时间线和官方证据。

产品定位从“精致日报看板”升级为：

> 日报入口 + 专业频道工作台 + 长期跟踪库。

## 2. 信息架构

一级产品入口保持克制，频道能力放入统一工作台：

```text
今日看板
├─ 各频道最新日报
├─ 今日重要事项
├─ 招投标即时机会
└─ 我的跟踪与最近节点

我的跟踪
├─ 已收藏
├─ 待复核
├─ 跟进中
├─ 等待公告或结果
└─ 已结束

频道工作台
├─ 上市公司
├─ 证券私募
├─ 拟上市与股权融资
├─ 收并购
├─ 金融招投标
└─ 国企动态

年度数据
主体关系
质量中心
```

日报、收藏、主体、时间线和证据必须引用同一份 `event`，不能复制事件形成第二套事实。

## 3. 统一收藏与跟踪机制

### 3.1 目标

用户看到有意义的事件后，可以立即保存，并在以后快速找到、更新和结束。

### 3.2 WatchItem 对象

每个跟踪项至少保存：

- `watchId`、`eventId`、`entityId`。
- `watchStatus`：`saved`、`to_review`、`following`、`waiting`、`resolved`、`closed`。
- `priority`、自定义标签和公开业务方向。
- `note`：用户自己的工作备注，与事件事实分离。
- `nextReviewAt`：下一复核时间。
- `createdAt`、`updatedAt` 和状态历史。

收藏不复制事件正文。事件更新后，收藏页自动看到最新节点，同时保留收藏时点和用户备注。

### 3.3 页面能力

- 信号、事件、公司、项目均可收藏。
- 支持按频道、主体、业务、状态和复核时间筛选。
- 首页显示最近到期的跟踪项。
- 已结束事件保留历史，不从年度库删除。

## 4. 上市公司工作台

### 4.1 四个固定视图

| 视图 | 目标 | 默认内容 |
|---|---|---|
| 最新日报 | 完整看到本次有效动态 | 当日全部有效新增和进展，不限首页重点条数 |
| 重要事项 | 只看真正值得处理的内容 | 风险、资本运作、业绩异常、重大经营和业务线索 |
| 财务报告 | 年报季报期间快速比较公司 | 财务表、同比、分红、异常项和报告期筛选 |
| 公司跟踪 | 查看一家公司从发现到结果 | 公司画像、收藏、事件时间线、待复核和最终状态 |

首页仍只展示 3 至 6 条最重要信号；上市公司“最新日报”展示本次全部有效事件，不设置 5 条上限，也不为凑数收录无意义事项。

### 4.2 财务报告模式

年报、季报、业绩预告和业绩快报进入统一财务表：

| 字段 | 说明 |
|---|---|
| 公司、代码、主体层级 | L1/L2/L3 及纳入依据 |
| 报告期、披露类型 | 年报、季报、预告、快报 |
| 营业收入及同比 | 保留单位和币种 |
| 归母净利润及同比 | 亏损和扭亏单独标识 |
| 扣非净利润及同比 | 未披露为 null |
| 经营现金流 | 与利润变化联动观察 |
| 毛利率、净利率 | 保留报告口径 |
| 分红和股息率字段 | 只使用公开披露值 |
| 业务结构 | 主要产品、收入占比及变化 |
| 异常项 | 大幅变化、审计意见、问询和风险 |

页面支持“日报模式 / 财务表模式 / 公司比较”切换。公司比较应支持选择多家公司和多个报告期，不把不同币种和口径直接相加。

### 4.3 跟踪机制

- 同一事项使用唯一 `eventId`。
- 公告、问询、回复、审议、结果和终止进入同一时间线。
- 重要事项可以收藏并设置下一复核时间。
- 历史最终结果保留在公司档案和年度数据中。

## 5. 证券私募工作台

### 5.1 固定分区

| 分区 | 核心问题 |
|---|---|
| 今日备案 | 今天新增了哪些产品、管理人和托管关系 |
| 活跃前20 | 陕西哪些证券私募近期公开活动最活跃 |
| 人员追踪 | 法人、实控人、投资负责人和合规负责人有什么变化 |
| 券商关系 | 公开资料显示管理人与哪些券商合作较多 |
| 壳体雷达 | 沉寂管理人是否疑似重新启用或发生重组 |
| 迁入迁出 | 哪些机构、办公地或核心人员进入和离开陕西 |

### 5.2 活跃前20口径

名称固定为“活跃度前20”，不能写成资产规模前20。建议评分维度：

| 维度 | 建议权重 | 依据 |
|---|---:|---|
| 最近12个月新增备案 | 30 | 产品备案日期和数量 |
| 最近一次备案新鲜度 | 20 | 距当前日期天数 |
| 当前公开产品数量 | 15 | AMAC 公开产品记录 |
| 连续备案能力 | 10 | 月度、季度备案连续性 |
| 人员和组织变化 | 10 | 高管、实控人、地址和股东快照差异 |
| 券商公开合作覆盖 | 10 | 托管、外包和公开产品合作信号 |
| 风险修正 | -15 至 0 | 异常、注销、长期无产品和来源缺失 |

每个分数必须可下钻到组成记录。缺少规模数据时不推断管理规模。

### 5.3 人员追踪

保存管理人每次成功快照，比较：

- 法定代表人和实际控制人。
- 投资负责人、总经理、合规风控负责人、信息填报负责人。
- 从业人数和基金从业资格人数。
- 核心人员公开履历和历史任职机构。
- 人员加入、离开、角色互换和长时间空缺。

人员变化必须显示前值、后值、发现时间、来源时间和核验状态。

### 5.4 券商公开合作指数

只能根据公开证据建立关系：

- 产品托管人。
- 外包服务机构和公开销售合作。
- 公告、招聘、官网或产品资料中的合作披露。
- 同一管理人不同产品的券商出现频次。

页面名称使用“公开合作指数”或“公开合作信号”，不能描述成未公开的真实业务紧密程度。

### 5.5 社会关系图谱边界

允许展示：股东、实控人、公开高管、历史任职机构、产品、托管券商、关联基金和企业。

不允许展示：无法回源的私人关系、聊天推测、人际亲疏和未经公开证实的利益关系。

### 5.6 壳体重新启用与迁入迁出

疑似重新启用信号包括：

- 长期无新产品后突然新增备案。
- 法人、实控人、投资负责人或合规负责人集中更换。
- 注册地址、办公地址、股东或实缴资本发生变化。
- 公开产品从零恢复或备案频率显著上升。
- 注销前后出现关联主体、人员或新管理人承接线索。

迁入迁出必须区分注册地、办公地和核心人员履历：

- 陕西注册地迁出或迁入。
- 办公地址迁出或迁入陕西。
- 核心人员从省外机构加入陕西管理人。
- 陕西核心人员进入省外重点机构。

以上均是观察信号，不能仅凭单项变化断言壳体交易或业务重启。

## 6. 收并购工作台

每个项目建立独立详情和状态时间线：

```text
首次线索
→ 停牌或筹划
→ 意向协议
→ 预案或草案
→ 董事会、股东会审议
→ 问询与回复
→ 监管批准
→ 付款和工商变更
→ 交割完成或终止
```

项目页固定展示：

- 买方、卖方、标的、关联主体。
- 交易比例、金额、估值、支付方式和融资安排。
- 中介机构和公开项目负责人。
- 当前状态、下一节点和风险条件。
- 完整公告时间线和证据。
- 关联的收藏、线索和其他频道事件。

每日只推送新时间线节点，不因进展增加年度项目数。

## 7. 拟上市企业与股权融资工作台

该频道作为正式独立工作台建设，覆盖：

- 陕西拟上市企业主名单和所属产业。
- 辅导备案、辅导进展、申报、问询、终止和上市。
- A股、北交所、新三板和港股进程。
- 历次融资、投资方、金额、估值和用途。
- 产业基金、国资平台和投资机构关系。
- 保荐、审计、法律和其他中介机构。
- 企业经营、项目、招投标和并购联动。

每家公司形成“融资成长档案”：

```text
早期融资 → 产业资本进入 → Pre-IPO → 辅导 → 申报 → 问询 → 上市 / 终止
```

未公开融资金额、轮次和估值保持 null，不根据新闻措辞补写。

## 8. 金融招投标即时发现层

### 8.1 运行节奏

V3 正式网页仍发布上午和盘后两个快照；招投标采集层独立提高到每 30 至 60 分钟扫描一次。符合条件时立即生成轻量提醒，不等待下一份日报。

### 8.2 发现流程

```text
官方页面发布招标、采购、遴选或征集公告
→ 保存正文、附件、发布时间和首次发现时间
→ 判断证券公司是否具备参与适配性
→ 提取资格条件、规模、截止和开标时间
→ 生成即时机会提醒并进入行动日历
→ 候选、中标、延期或终止更新原项目时间线
```

### 8.3 强约束

- 只有公告阶段发现且截止时间仍有效，才能进入机会区。
- 候选、中标和成交结果不得包装成新机会。
- 搜索摘要只能发现候选，必须回到官方公告正文。
- 必须记录 `publishedAt`、`discoveredAt`、`deadlineAt` 和剩余小时。
- 首次发现已截止或处于结果阶段，进入历史项目和漏检复盘。
- 同一漏检原因连续两次出现，必须增加来源、检索词或自动测试。

### 8.4 来源策略

优先建立官方来源注册表和页面差异监控，覆盖陕西招投标平台、采购平台、国企采购栏目、资本平台和重点发行主体。搜索引擎只做补漏，不作为主发现机制。

## 9. 跨频道主体和关系底座

统一关系边至少保存：

- `relationshipId`、起点和终点 `entityId`。
- 关系类型：股东、实控、任职、托管、投资、并购对手、采购人、中介等。
- `validFrom`、`validTo`、`discoveredAt`。
- `sourceRecordIds`、核验状态和置信度。

关系图用于检索和理解，不替代事件事实。所有关系必须可回源。

## 11. 研发纪律

- 严格按 Phase 1 至 Phase 6 推进，不跨阶段堆叠未验证功能。
- 每阶段先补 Schema、真实样例和验证器，再修改页面。
- 不使用虚构机构、人员、融资或招标项目填充页面。
- 新页面必须继承 V3 去重、时间、来源、Provider 和排除规则。
- 本蓝图改变产品逻辑时，必须同步更新决策日志和受影响 SOP。
- 当前本地原型继续可用；开发不得影响 V1 日常生产。

## 12. 下一阶段入口

Phase 1 至 Phase 6 蓝图已完成。后续工作只沿技术成熟度路线推进：把上市公司与私募输入从固定样例升级为运行日适配器，连续观察上午/盘后运行记录，再决定正式发布；不得以继续增加页面代替数据当日化，也不得破坏 V1 生产。
