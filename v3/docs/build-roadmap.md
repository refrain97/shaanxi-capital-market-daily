## 2. 实现阶段

| 阶段 | 目标 | 主要产物 | 验收标准 |
|---|---|---|---|
| P0 文档基线 | 固化产品、流程和强约束 | `docs/00-08`、`config/data-providers.json` | 上下文压缩后可独立恢复，已完成 |
| P1 数据骨架 | 落实体、事件、信号、线索和快照 Schema | `schemas/*.schema.json`、目录骨架 | 六频道均可映射，时间和 ID 规则明确 |
| P2 真实样例 | 用 2026-07-10 数据建立首批主数据 | `examples/2026-07-10/` | 能识别重复、回溯、无新增和行动窗口 |
| P3 质量闸门 | 将强约束机器化 | `validators/`、Provider 探针、测试夹具 | 别名重复、截止、来源、Provider 路径和统计错误能被阻断 |
| P4 两条纵向链路 | 先跑通上市公司和招投标 | 只读适配器、事件合并、快照 | 从 V1 数据到 V3 页面全链路可复现 |
| P5 业务看板 | 实现首页、信号流、年度数据和详情 | `site/` | 首屏 30 秒标准、KPI 可下钻、移动端可用 |
| P6 全频道接入 | 接入私募、股权融资、收并购、国企雷达 | 六频道适配器和年度表 | 所有频道使用同一实体和事件库 |
| P7 两次更新 | 实现上午、盘后调度与差异快照 | 统一运行入口、运行记录 | 两次更新不重复建事件，异常可降级 |
| P8 发布试运行 | 并行发布 V3，不影响 V1 | 独立 V3 地址和回滚 | 连续试运行、线上验证、质量记录完整 |

业务蓝图 Phase 1 至 Phase 6 已完成。后续不再横向新增页面，进入技术成熟度路线：将上市公司与私募源适配器当日化、连续并行试运行并完成正式发布验收。现有 P0-P8 回答“做到什么生产程度”。

## 3. 页面实现顺序

页面开发必须使用 P2 的真实样例，不使用虚构演示数据替代验收。

1. 今日看板骨架。
2. 信号流和详情抽屉。
3. 我的跟踪、状态编辑和最近复核。
4. 年度数据总览和明细表。
5. 业务线索看板和截止日历。
6. 主体雷达和跨频道时间线。
7. 质量中心。

## 4. 第一批真实样例

使用 2026-07-10 的现有 V1 内容验证模型：

- 上市公司：识别陕西能源/长安汇通、美畅股份/钨丝金刚线等别名重复。
- 上市公司主体池：加入 L1/L2/L3 分层，并以11家逐家复核的强关联公司验证纳入依据和排除规则。
- 招投标：区分公告期机会、结果进展和回源核验。
- 私募：将年内累计产品与本次新增差异分离。
- 收并购：把 24 个写死案例转换为唯一事件及时间线。
- 国企雷达：过滤一般宣传内容并建立主体关系。

## 5. V1 继承方式

- V1 保持稳定运行，不作为 V3 页面模板。
- 上市公司可读取 V1 的 CNINFO JSON、PDF 文本和精读数据。
- 私募可读取 V1 的 AMAC 原始 JSON，但重新做快照差异。
- 收并购和招投标先把现有累计内容迁移为事件库，再停止写死数据。
- V3 不复制 V1 原始 PDF、历史图片和完整发布目录。

## 6. 开始写 UI 前的门槛

以下条件未满足时，只能做线框讨论，不进入正式页面实现：

- `entity`、`event`、`signal`、`lead`、`snapshot` Schema 可校验。
- 2026-07-10 样例已落盘。
- 至少 `DEDUP`、`TIME`、`SRC`、`PROV`、`STAT` 五组 BLOCK 规则有测试。
- 年度统计可以从样例事件库计算并下钻。
- 首页 KPI 不依赖手写数字。

## 7. 试运行验收

V3 上线前至少完成一段并行试运行，重点观察：

- 上午和盘后是否稳定区分。
- 招投标是否在公告期捕捉。
- 同一事件是否跨日重复。
- 无新增时是否保持真实空状态。
- 年度统计是否随事件状态正确更新。
- 页面是否比 V1 更快找到行动事项和历史数据。
