# V3 业务看板与年度数据表现规范

版本：0.3  
生效日期：2026-07-11  
定位：规定 V3 页面怎样才算精准、好用、年轻且可长期浏览

## 1. 总体原则

V3 的视觉外层借鉴轻量产品站的节奏与质感，内层采用现代管理后台和 BI 看板的信息密度。参考方向为 `iamrob`、`pixelwrld` 的清爽产品感，`shadcn-admin` 的交互结构，以及 Power BI Design Files 的数据组织方式。

界面必须服务业务判断，不能为了视觉效果牺牲信息完整性。

- 首页是实际可用的情报入口，不是营销落地页。
- 首屏展示本次变化和行动，不展示档案数量作为核心价值。
- 年度数据使用图表、表格、筛选器和详情抽屉，不使用超长图片。
- 同一信息只在一个主位置完整展示，其他位置使用短引用。
- 卡片只承载独立信号或指标，不用卡片包裹整个页面区块。

## 2. 页面架构

V3 至少包含以下页面：

| 页面 | 默认问题 | 主要内容 |
|---|---|---|
| 今日看板 | 本次更新要看什么 | 重点信号、行动窗口、风险、数据变化 |
| 上市公司 | 本次完整披露和公司变化是什么 | 最新日报、重要事项、财务报告、公司跟踪 |
| 招投标机会 | 现在有哪些仍可响应的项目 | 有效机会、扫描运行、历史漏检、官方来源 |
| 我的跟踪 | 哪些事项需要持续复核 | 收藏事件、工作备注、状态、优先级、下一复核时间 |
| 信号流 | 本次有哪些新增和进展 | 可筛选信号列表 |
| 业务线索 | 哪些值得跟进 | 线索、对象、动作、截止、状态 |
| 年度数据 | 今年发生了多少和如何变化 | 趋势、结构、排名、明细表 |
| 主体雷达 | 某主体今年发生了什么 | 主体画像、跨频道时间线、关联关系 |
| 证据详情 | 结论依据是什么 | 来源、正文证据、数字、校验记录 |
| 质量中心 | 哪里可能漏了或失效 | 来源健康、待核验、漏检复盘 |

## 3. 今日看板

桌面端固定采用以下信息骨架，后续原型不得另起一套首页逻辑：

```text
┌──────────────┬──────────────────────────────────────────────────────┐
│ 陕西资本市场  │ 日期  上午/盘后  数据截止  上次成功  来源状态         │
│              ├──────────────────────────────────────────────────────┤
│ 今日看板      │ 新增信号 | 行动窗口 | 风险 | 数据更新 | 待核验       │
│ 信号流        ├──────────────────────────────┬───────────────────────┤
│ 业务线索      │ 今日最重要 3-6 条             │ 行动窗口 / 最近截止    │
│ 年度数据      │ 事实、数字、业务映射、状态     │ 对象、动作、剩余时间    │
│ 主体雷达      ├──────────────────────────────┴───────────────────────┤
│ 质量中心      │ 本次变化：新增 / 进展 / 关闭 / 回溯                  │
│              ├──────────────────────────────────────────────────────┤
│              │ 六频道摘要：上市 / 私募 / 融资 / 并购 / 招投标 / 国企 │
│              ├──────────────────────────────┬───────────────────────┤
│              │ 今年趋势与结构                │ 未来 30 天行动日历      │
│              ├──────────────────────────────┴───────────────────────┤
│              │ 重点主体与质量、漏检提示                              │
└──────────────┴──────────────────────────────────────────────────────┘
```

移动端按“状态栏、KPI、今日最重要、行动窗口、本次变化、年度摘要、频道入口”纵向排列，年度明细表切换为分组列表。

构图纪律：

- 默认入口就是当前成功快照的“今日看板”，不设置营销首页或日报文件目录。
- 上午版和盘后版使用同一页面、同一事件库，通过分段控件切换。
- 左侧导航只保留六个产品级入口；六个业务频道放在今日看板和年度数据内部筛选，不再各自做一套首页。
- 首屏主体区域采用约 `2:1` 的信息比例：左侧看重要事项，右侧看可执行窗口。
- 六频道摘要使用紧凑行或分段列表，展示本次新增、行动中、风险和最近更新，不制作六张大装饰卡。
- 点击信号、线索、主体和 KPI 优先打开右侧详情抽屉；需要完整证据或跨期浏览时再进入独立详情页。
- 首页不直接堆完整公告、长篇分析和全年明细，完整内容进入详情、年度表和证据层。

### 3.1 顶部状态栏

固定展示：

- 产品名称：`陕西资本市场情报`。
- 报告日期与 `上午更新 / 盘后更新`切换。
- 本次更新时间、数据截止时间、上一成功更新时间。
- 来源健康状态。

### 3.2 首屏 KPI

只展示对行动有意义的指标，建议为：

- 本次新增信号。
- 当前行动窗口。
- 风险预警。
- 本次数据表更新。
- 待核验或漏检数量。

KPI 必须可以点击进入对应筛选结果。没有数据时显示 `0` 和明确空状态，不用历史累计填充首屏。

### 3.3 首屏主体内容

首屏下半部分按以下顺序：

1. `今日最重要`：最多 3-6 条，由评分和人工判断决定，不固定凑数。
2. `行动窗口`：按截止时间升序，显示剩余天数、业务方向和下一步动作。
3. `本次变化`：上午与盘后、上一快照与当前快照的差异。

重点信号卡最少包含：

- 状态标签和频道。
- 主体名称和事件标题。
- 一句话事实。
- 关键数字。
- 业务映射。
- 下一步动作或查看详情。
- 来源质量标识。

### 3.4 第二屏内容

- 年度趋势摘要。
- 上市公司、私募、股权融资、收并购、招投标、国企雷达六个模块入口。
- 未来 30 天行动日历。
- 质量和漏检提示。

国企雷达必须作为主入口模块存在，并能跳转到主体视图；不以孤立网页或图片嵌入代替数据联动。

## 4. 上市公司工作台

固定使用四个视图：

- `最新日报`：展示本次全部有效事项，不受首页重点条数限制；显示公告份数和归并原因。
- `重要事项`：只保留风险、资本运作、业绩异常、重大经营和明确业务节点。
- `财务报告`：支持财务表、公司比较和报告期筛选；空值、币种、预告/正式口径必须可见。
- `公司跟踪`：按公司查看本期公告、事件时间线、财务记录、收藏与复核。

同一事项的多份公告在列表中合并，详情抽屉必须提供全部原始公告入口。首页继续只展示3至6条重点信号，不得用首页数量代替完整日报数量。

## 5. 招投标机会

固定使用四个视图：

- `有效机会`：只展示公告阶段、截止有效、资格适配且已回源项目；允许真实空状态。
- `扫描运行`：展示目标频率、调度状态、候选、结果和排除，不隐藏失败或未启用状态。
- `历史与漏检`：首次发现已截止或处于结果阶段的项目，显示公告、截止、发现时间和漏检原因。
- `官方来源`：来源入口、权威级别、覆盖阶段、扫描目标和组合检索词。

当前调度未启用时必须在首屏明确显示，不得以静态样例冒充实时监控。

## 6. 年度数据浏览页

### 6.1 顶部筛选区

筛选器采用紧凑工具栏，不使用大面积表单。至少支持：

- 年份、季度、月份和自定义日期。
- 频道。
- 主业务和辅助业务。
- 主体、地区和主体类型。
- 事件状态、行动状态和质量状态。
- 金额区间、是否有截止日、是否产生线索。

筛选条件应写入 URL，刷新或分享后仍可恢复。

### 6.2 年度总览

年度页第一层回答四个问题：

1. 今年累计发生多少唯一事件。
2. 最近一个月新增和变化趋势如何。
3. 哪些业务、主体和事件类型最集中。
4. 当前还有多少事项在行动或跟踪中。

推荐图表：

- 月度新增事件折线或柱线组合。
- 业务类型结构条形图。
- 主体活跃度排名。
- 状态漏斗：发现、核验、推送、跟踪、结果、归档。
- 截止日分布和未来 30 天日历。

饼图只在类别不超过五个且比例比较确有价值时使用。

### 6.3 明细表

年度明细表是核心，不是图表附属。默认字段：

| 字段 | 说明 |
|---|---|
| 日期 | 事件发生或公告日期 |
| 主体 | 规范化主体名称 |
| 事件 | 简洁标题 |
| 频道 | 来源频道 |
| 业务 | 主业务映射 |
| 状态 | 当前事件和行动状态 |
| 关键数字 | 金额、比例、人数、产品数等 |
| 截止 | 截止日期或无 |
| 最新进展 | 最近时间线节点 |
| 质量 | 已回源、交叉核验、待核验 |

表格必须支持排序、筛选、列显隐、固定表头、导出当前筛选结果和打开详情。默认每页不超过 50 行；移动端改为紧凑列表，不强行压缩所有列。

### 6.4 指标计算纪律

- `累计事件数` 按唯一 `eventId` 去重。
- `主体数` 按唯一 `entityId` 去重。
- `新增` 以本次首次进入事件库为准。
- `进展` 是既有事件新增时间线节点，不计新事件。
- `行动窗口` 必须满足状态和截止日期规则。
- 所有指标可下钻至组成明细。

## 7. 信号流

信号流默认按本次快照显示，可切换今日、本周、本月和自定义区间。

每条信号只展示一次，支持按以下方式切换：

- 状态：新增、进展、回溯、观察。
- 优先级：高、中、低。
- 业务：投行、债券、并购、私募服务等。
- 频道和主体。

信号流中的短摘要不重复详情页全文；同一事件在首页、频道页和主体页只引用同一 `signalId`。

## 8. 业务线索看板

线索看板采用列表或轻量看板列，默认状态：

`待判断 -> 待联系 -> 跟进中 -> 等待节点 -> 已转化 -> 已关闭`

每条线索展示：

- 对象及关联事件。
- 主业务和机会类型。
- 业务依据。
- 建议动作。
- 到期或复核时间。
- 当前状态、优先级和置信度。

V3 只提出公开信息下的线索建议，不把建议写成已经联系、已经承揽或已经成交。

## 9. 主体雷达

主体页是跨频道聚合入口，必须包含：

- 标准名称、别名、主体类型、地区和关联主体。
- 今年事件数、行动中事项、风险和最近更新时间。
- 跨频道时间线。
- 业务分布和关键数字。
- 关联的招投标、融资、并购、公告、私募或国企事件。
- 相关线索及下一步节点。

同一国企集团及其子公司要能通过关系字段聚合，也要允许查看单一子公司。

## 10. 详情与证据

详情页按以下顺序展示：

1. 事实摘要。
2. 当前状态和关键时间。
3. 关键数字。
4. 业务判断和下一步动作。
5. 事件时间线。
6. 关联主体、事件和线索。
7. 来源、证据摘录、抓取时间和校验状态。

证据内容可折叠，但不能隐藏来源类型和质量状态。

## 11. 视觉与交互规范

- 整体年轻、轻量、克制，避免一整页深蓝、紫色或米色单一配色。
- 主色用于导航和关键状态，风险、行动、成功、待核验使用不同语义色。
- 卡片圆角不超过 8px，表格和工具栏优先直观、紧凑。
- 使用统一图标库，按钮图标含工具提示。
- 不使用装饰性渐变球、背景光斑和无业务含义插画。
- 页面标题适中，不使用营销式超大 Hero 占满首屏。
- 所有日期、数字、主体名在移动和桌面端不得重叠或截断关键含义。
- 空状态写明“本次无新增”或“当前筛选无数据”，不放假数据填充。

## 12. 验收标准

表现形式只有同时通过以下检查才算好：

- 首屏 30 秒标准通过。
- 任意 KPI 可下钻并与明细数量一致。
- 年度筛选结果可复现、可分享、可导出。
- 同一事件不会在同一页面重复长写。
- 移动端能完成查看重点、筛选和打开详情三个核心动作。
- 桌面端能在不滚动超长图的情况下浏览年度数据。
- 页面明确区分事实、判断、建议和证据。
- 无新增、来源失败和待核验状态表达真实。
