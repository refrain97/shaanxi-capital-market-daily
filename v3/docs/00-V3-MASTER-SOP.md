# 陕西资本市场情报 V3 总 SOP

版本：0.3  
生效日期：2026-07-11  
状态：权威流程基线  
适用范围：V3 的数据采集、内容判断、业务看板、年度统计、发布和复盘

## 1. 产品定义

V3 是每天更新两次的陕西资本市场机构情报系统。它不以“每天必须生成几张日报”为目标，而以以下结果为目标：

1. 及时发现当天真正新增的事项。
2. 判断事项是否仍有行动窗口。
3. 把客观数据整理成可筛选、可比较、可回溯的年度台账。
4. 把高价值事项转化为有依据的业务线索和下一步动作。
5. 保留来源、证据、发现时间和状态变化，支持复核和漏检复盘。

V3 的一句话定义：

> 每天两次更新、以行动窗口和线索建议为核心、以年度事件库为底座的陕西资本市场业务看板。

## 2. 什么叫表现形式做得好

### 2.1 首屏 30 秒标准

观众不打开详情，在首屏 30 秒内应能回答：

- 本次更新新增了什么。
- 哪些事项现在还能行动。
- 最近的截止时间是什么。
- 每条重点信号对应哪类证券业务。
- 哪些事实已经回源，哪些仍待核验。

如果首屏首先展示日报数量、文件格式、历史长图或流程说明，而不能回答以上问题，则表现形式不合格。

### 2.2 一分钟业务标准

观众进入任一信号后，一分钟内应能看到：

- 主体和事件的唯一身份。
- 发生时间、公告时间、发现时间和截止时间。
- 关键数字及同比、环比或前后变化。
- 为什么与业务有关。
- 建议动作、验证节点和当前状态。
- 官方来源、证据摘要和数据质量。

### 2.3 年度统计标准

年度页不是每日图片归档，而是从唯一事件库实时计算的可浏览数据。必须支持按以下维度筛选：

- 时间：年、季度、月份、自定义区间。
- 主体：公司、集团、管理人、基金、项目、人员。
- 频道：上市公司、证券私募、股权融资、收并购、招投标、国企雷达。
- 业务：投行、债券、并购、财富与机构销售、私募服务、股权融资、研究、客户维护。
- 状态：新增、行动窗口、跟踪、结果、终止、回溯补录、漏检复盘。
- 质量：已回源、交叉核验、待核验、来源异常。

同一事件跨日存在时只能计数一次，年度统计不得把每日快照相加。

## 3. 用户视角和信息层级

V3 同时服务三个使用层级：

| 层级 | 用户问题 | 默认表现 |
|---|---|---|
| 决策层 | 今天最重要的是什么 | 重点信号、行动窗口、风险和质量摘要 |
| 业务层 | 我该联系谁、什么时候做什么 | 线索看板、截止日历、主体视图 |
| 研究层 | 今年发生了多少、结构如何变化 | 年度统计、趋势、排名、事件明细 |

页面由浅入深，固定为四层：

1. `Dashboard`：今日判断和行动入口。
2. `Explorer`：年度数据浏览和筛选。
3. `Entity`：主体全景和跨频道时间线。
4. `Evidence`：原始来源、证据和校验记录。

## 4. 统一生产链路

V3 的唯一标准流程为：

```text
运行前体检
  -> 分源采集
  -> 原始记录落盘
  -> 实体规范化与别名归一
  -> 事件识别与事件库合并
  -> 时间、来源和证据核验
  -> 业务分类与重要性评分
  -> 生成 signal 和 lead
  -> 形成 morning / closing 快照
  -> 渲染业务看板与年度数据页
  -> 质量闸门
  -> 发布与线上验证
  -> 运行记录、漏检复盘和归档
```

任何页面和推送都必须来自结构化对象，不允许直接从搜索摘要或上一期 HTML 改日期生成。

## 5. 两次更新节奏

### 5.1 上午更新 `morning`

目标：回答“今天一开始要知道和行动什么”。

重点处理：

- 上一交易日收盘后至本次运行的上市公司公告。
- 新发布的招标、采购、遴选和征集公告。
- AMAC 新增、注销、产品和人员快照变化。
- 国企、拟上市主体和股权融资新增事件。
- 昨日未完成核验但今日仍有行动价值的事项。

主要输出：今日新增、行动窗口、风险预警、最近截止、待核验高价值项。

### 5.2 盘后更新 `closing`

目标：回答“今天发生了什么变化，明天继续看什么”。

重点处理：

- 日内新增公告和结果进展。
- 上午信号的正文回源、数字修正和状态变化。
- 年报季报、私募、融资、并购等结构化表格更新。
- 线索建议、明日跟踪和漏检复盘。

主要输出：日内变化、数据表更新、线索复盘、明日跟踪、质量说明。

### 5.3 快照原则

- 上午和盘后是同一事件库的两个快照，不是两套数据。
- 盘后更新同一事件时追加状态历史，不重复创建事件。
- 页面必须显示本次运行时间、数据截止时间和上一成功快照。

## 6. 从采集到发布的标准步骤

### 6.1 运行前体检

检查日期、时区、网络、来源可访问性、公司池和主体池版本、上一成功快照、事件库可读性、发布目标和本地磁盘空间。

金融数据服务必须读取 `config/data-providers.json`，按 `08-V3-DATA-PROVIDERS.md` 从指定路径发起本班次真实探针。skill 目录存在、环境变量名称存在或上午调用成功，都不能替代当前班次真实请求。

来源不可访问时不得用旧数据冒充新数据。必须记录 Provider ID、调用路径标识、状态、失败时间、影响频道和降级状态，但不得记录任何密钥或鉴权内容。

### 6.2 分源采集

- 每个来源独立采集并记录 `sourceRunId`。
- Wind 默认仅从已验证的 `~/.codex/skills/wind-mcp-skill` 调用；iFinD 从 `~/.codex/skills/ifind-finance-data` 调用。其他同名副本必须独立探针并显式登记后才能切换。
- 保存原始标题、正文或附件引用、发布时间、抓取时间和原始 URL。
- 采集范围由频道 SOP 决定，不由页面栏位数量决定。
- 搜索引擎和聚合页只用于发现，不能自动成为高质量事实来源。
- Wind 与 iFinD 用于结构化数据和交叉核验，公告关键事实最终以官方披露为准；双源冲突不得静默选值。

### 6.3 实体规范化

先把公司、股东、子公司、集团、人员、基金和项目映射到稳定 `entityId`。简称、全称、证券简称、历史名称和子公司名称进入别名表。

无法确认实体时进入待核验池，不得为了出稿临时把“红利发放”“薪酬事项”“钨丝金刚线”等主题词写进公司字段。

### 6.4 事件识别与合并

判断新记录属于：

- 新事件。
- 既有事件的状态进展。
- 同一公告的重复来源。
- 历史事件补录。
- 无业务意义的排除样本。

同一事项必须使用唯一 `eventId`；公告、结果、问询、回复和终止作为事件时间线节点保存。

### 6.5 证据和时间核验

逐项核对来源等级、关键数字、主体、事件时间和行动截止日。上市公司关键事实优先使用 CNINFO/交易所 PDF；招投标新增机会优先使用公告正文；私募使用 AMAC 公示及前后快照。

必须区分：`occurredAt`、`publishedAt`、`discoveredAt`、`deadlineAt`、`resultAt`、`lastCheckedAt`。

### 6.6 业务分类与评分

每个有效事件映射一个主业务和可选辅助业务。评分只用于排序，不替代人工判断。

建议评分维度：

| 维度 | 分值 | 含义 |
|---|---:|---|
| 业务适配度 | 0-30 | 与证券业务和客户服务的直接相关性 |
| 行动紧迫度 | 0-25 | 截止期、窗口期和响应速度 |
| 影响程度 | 0-20 | 金额、主体层级、风险和市场影响 |
| 新颖程度 | 0-15 | 相对上一快照是否有实质新增 |
| 证据质量 | 0-10 | 官方来源、正文完整度和交叉核验 |

总分不等于真实性。证据不达标时，即使高分也只能待核验。

### 6.7 生成信号与线索

- `event` 记录事实。
- `signal` 解释为什么值得看。
- `lead` 记录业务动作。

每个事件最多有一个主信号。一个信号可以关联多个主体和业务，但不得在不同栏目重复长写。

线索建议必须包含：业务方向、对象、依据、下一步动作、截止或复核时间、置信度。无法给出下一步动作的内容只能是信息信号，不能标为业务线索。

### 6.8 生成快照和页面

快照只保存本次新增、变化、仍在行动窗口和需要继续跟踪的对象引用。年度页直接读取事件库和派生指标，不复制每日页面内容。

页面表现必须遵循 `01-V3-PRESENTATION-SPEC.md`。

### 6.9 质量闸门

按 `04-V3-QUALITY-GATES.md` 执行。阻断项未通过时：

- 不得发布正式快照。
- 不得写“已完成”或“已发布”。
- 可以发布明确标注的降级状态页，但不得隐藏缺失来源。

### 6.10 发布与验证

发布后必须验证：

- 线上首页显示正确快照和更新时间。
- 重点信号、年度页、详情页和证据链接可打开。
- 手机和桌面无横向溢出、遮挡和空白主区域。
- 页面统计与事件库查询结果一致。
- 上一成功版本可回滚。

## 7. 无新增日的处理

无新增是一种有效结果，不需要制造日报。

- 更新来源运行记录和 `lastCheckedAt`。
- 快照写明“本次检查无实质新增”。
- 年度统计保持不变。
- 仍在行动窗口的旧事件可以继续显示，但必须标明原公告日期和剩余时间。
- 不复制上一期 HTML、PNG 后只替换日期。
- 不向 IMA 或历史归档重复上传相同累计长图。

## 8. 低质量和异常处理

| 情况 | 处理 |
|---|---|
| 官方源不可用 | 记录来源失败，保留待核验，不冒充完整运行 |
| 仅命中搜索摘要 | 可建候选，不得建已确认事件 |
| 正文缺失关键数字 | 明确缺失字段和复核任务 |
| 截止日期未知 | 不得默认处于行动窗口 |
| 首次发现已到结果阶段 | 建回溯事件并触发漏检复盘 |
| 同一主体名称不一致 | 先更新别名表，再合并事件 |
| 统计突变 | 暂停发布相关指标，做源数据差异检查 |

## 9. 记录与审计

每次运行必须形成运行记录，至少包含：

- `runId`、日期、快照类型、开始和结束时间。
- 各来源成功、失败和记录数。
- 新事件、更新事件、排除、待核验和漏检数量。
- 阻断项、警告项和人工判断。
- 发布地址、线上验证和上一成功版本。

用户确认的新要求必须更新 SOP 和 `06-V3-DECISION-LOG.md`，不能只在聊天中保留。

## 10. 完成定义

一次 V3 更新只有同时满足以下条件才算完成：

1. 计划来源完成采集或明确记录降级。
2. 实体、事件、时间和来源字段通过强校验。
3. 新增、进展、回溯和无新增状态没有混用。
4. 重点信号有业务解释，线索有下一步动作。
5. 本次快照和年度统计由同一事件库生成。
6. 页面通过桌面、手机和数据一致性检查。
7. 线上页面及关键链接实测可访问。
8. 运行记录、质量结果和决策变更已落盘。
