```markdown
### D-XXX｜标题

- 日期：YYYY-MM-DD
- 用户要求：...
- 决定：...
- 原因：...
- 影响文件：...
- 是否新增强约束或测试：是/否
```

## 修改纪律

- 新要求改变产品逻辑时，先更新本日志和对应 SOP，再开始实现。
- 仅修改文案或视觉细节时，也要在相关规范记录，不必新增重大决策编号。
- 被废止的决定不删除，标记 `已废止` 并引用替代决定。
- 实现完成后在路线图更新状态，不能只在聊天中说已完成。
